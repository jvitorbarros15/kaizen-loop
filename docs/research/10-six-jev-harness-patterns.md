# Six ways agent harnesses use Jev-like decisions

Sam Witteveen’s diagram identifies six decisions with different inputs, consequences, and feedback signals. A community implementation demonstrates that a harness can resolve several related decisions in one request. The per-turn Jev router selects the model tier, reasoning effort, tools, and skill before dispatching work. It includes a Claude Agent SDK adapter, a deadline, and a fallback. Its author reports about 350 ms for the decision call and explains that the default deadline was fitted on one machine. ## How the six interact in one run

Suppose CI produces 500 events for a broken export test. Filtering collapses repeated lines while retaining the first error and the final exit status. Triage assigns the failure to code repair. Model routing chooses the worker tier. Tool and skill selection supplies the CSV skill and focused test tool. Ranking puts the failing fixture and serializer ahead of unrelated files. Risk gating checks the actual operation before execution. After the patch, judging can flag an unsupported claim in the worker’s report, while the acceptance test records whether the repair worked.

Each decision leaves different evidence for improvement. A missing fixture points to retrieval or ranking. An unnecessary escalation points to routing. An interrupted authorized action points to the gate. Replay the earliest suspected decision, then rerun the complete task because later decisions see different evidence. Compare one added decision at a time against the existing harness. The CI sequence is a proposed coding application. The public examples above comprise published code, cookbooks, and research evaluations. Their production usage and the savings on this workspace are unmeasured.
